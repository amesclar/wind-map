# Release Notes - v0.13.3

This release is about the map key. Every row now says what its glyph means, where its value sits,
and which way the glyph points, and the wave key glyphs are cropped to the ink so their values sit
against their symbols.

Two of the glyph changes — counted wavy lines for waves and the orientation lines — went out in the
0.13.2 image but were not in its notes; they are documented here.

---

## Changes

- **Wind values beside their glyphs (SCRUM-303):** the wind row stacked each knot value under its
  barb and nudged the `Wind (kt)` label up the left edge, so it was two lines tall while the
  currents and waves rows put each value beside its glyph. All three rows now use the same inline
  layout.
- **A wider card, one step larger (SCRUM-296):** the key is 300 px wide with 10 px type instead of
  248 px and 9 px. The four wave swatches and the orientation lines each fit on one line, including
  on a 375 px phone.
- **Aligned rows, larger barbs (SCRUM-304):** the key rows sit on a column grid with a fixed glyph
  slot, and the wind barbs draw at 28 px instead of 20, so their ink is as tall as the chevrons'.
- **Wave key glyphs cropped to their ink (SCRUM-305):** each key glyph now carries its own bounds, so
  a one-line glyph no longer leaves most of a 20 px box empty. Values start a constant 4 px from the
  ink, as in the currents row.

## Also in this build

- **Waves as counted wavy lines (SCRUM-292):** the wave layer draws one wavy line per height tier —
  one at 0–1 m, two at 1–2 m, three at 2–4 m, four at 4+ m — each ending in one chevron head, with
  colour still by height. Currents keep the open chevrons: head count and colour for speed,
  orientation for flow. The two layers can be read apart at map size.
- **Orientation lines (SCRUM-294):** each key row states which way its glyph points — the barb's
  staff points where the wind comes from, the chevron points where the water flows, the wave heads
  point where the waves travel. The key's `aria-label` carries the same sentences.

**Upgrade notes:** no schema, data or configuration change. A hard reload clears a cached key if the
old one lingers.
