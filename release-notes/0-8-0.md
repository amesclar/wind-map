# Release Notes - v0.8.0

Release v0.8.0 delivers the map export epic (SCRUM-114): save the map exactly as it looks as a
printable PNG, JPEG or PDF, for a single forecast hour or a whole time range. Exports carry their
own header, legend and attribution, keep the selected model and units, and can be captured one file
per hour as a ZIP or as a multi-page PDF. The release also makes the exported legend agree with the
screen's wind colour scale and hardens range capture against slow or throttled grid requests.

---

## What's New

### Map export (SCRUM-116, SCRUM-117, SCRUM-157, SCRUM-162, SCRUM-163)
- **One click, printable:** the download-icon button beside Preferences opens a "Download map image" dialog for the view on screen. Export at 2x as PNG or JPEG (with a quality choice), or as a single-page PDF on Letter or A4 in portrait or landscape.
- **What goes in the file:** the map area, base map, wind barbs, colour overlay and saved-location markers, plus a header with the valid hour in your timezone and UTC, the model, its run and the capture time; a legend for the barbs and temperature colours; and a footer with units, map attribution and `Wind Map v<version>`.
- **Clean image:** Leaflet controls and pop-ups stay out, and tiles are painted into the canvas with the OSM dark filter re-created, so the export matches the screen.
- **Names that mean something:** files are named after the selected model and shown hour, e.g. `ecmwf_ifs_2026-11-18_1400PST.png` or `best_match_2026-11-23_1400PST.pdf`. The name is editable before export; reserved characters are removed and the extension follows the format.
- **No new server work:** capture happens in the browser. The capture, PDF and ZIP libraries load only when you export.

### Range exports (SCRUM-155, SCRUM-156, SCRUM-164, SCRUM-166)
- **A range of hours:** the dialog switches to Range mode, where you pick a start hour, an end hour and an interval of 1, 2, 3, 6 or 12 hours within the model's forecast window. A summary names the capture count and hours, and the range is capped at 24 captures with a clear message when it is too large.
- **One frame per hour:** each frame waits for that hour's grid data, captures once, and shows "n of N · capturing <hour>" with a Stop button. Cancelling downloads nothing and restores the hour, view and overlays you started from; a failure names the hour and offers the frames captured so far.
- **ZIP or multi-page PDF:** PNG and JPEG ranges save as one ZIP with one image per hour; PDF ranges save one file with one page per hour, fitted to the chosen page size and orientation. A one-hour range downloads its image directly. Archive names include the model, first hour and frame count, e.g. `best_match_2026-11-23_1400PST_5hours.zip`.
- **More reliable in the field:** each hour's grid data gets 60 seconds instead of 15 (SCRUM-164); a whole UTC day of grid data is now served from one upstream Open-Meteo call and throttled (429) requests are retried (SCRUM-166), so a 24-frame range no longer makes 24 separate upstream calls.

### Screen and export agree (SCRUM-165)
- With the wind colour gradient on, the exported legend draws the same wind-speed colour scale as the strip on screen — the same `COLOR_STOPS` at the same positions and the same tick labels from `legendTicks()` in your speed unit. The barb row keeps its glyphs and is captioned `Wind barbs (kt) · colour = temperature (°F)`, and the temperature swatch row is omitted. With the gradient off, the legend is unchanged.
- Both legends now share `utils/windColorScale.ts`, so the screen and export cannot drift apart. A four-unit sync test guards knots, km/h, mph and m/s.

### User-testing polish (SCRUM-158, SCRUM-159, SCRUM-160)
- The version badge and `/api/health` show the build hash (`0.8.0-<short-hash>`) so a running container can be matched to a commit; `VERSION`, `package.json` and tags stay plain semver.
- The export trigger uses the supplied download artwork, sized like the Preferences gear, and the dialog wording and editable file name came out of user testing recorded in `requirements.md`.
- The AI rules are split into tiers so `AGENTS.md` stays inside Devin's prompt budget; the generated rule files are synced from `.kiro/steering/`.

## Compatibility
- **API:** no breaking changes. Existing weather endpoints and responses are unchanged; range exports are entirely client-side.
- **Data:** saved locations, preferences, units and forecast caches are untouched; no schema migration is required.
- **Dependencies:** `modern-screenshot` 4.7.0, `jsPDF` 4.2.1 and `fflate` are pinned, loaded lazily, and `npm audit --omit=dev` reports 0 vulnerabilities.
