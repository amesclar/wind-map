# Release Notes - v0.13.2

Two fixes for what 0.13.0's security headers did to the map and its base tiles.

---

## Fixes

- **The map draws again (SCRUM-293):** `index.html` loaded Leaflet's stylesheet from
  `unpkg.com`, and the new `Content-Security-Policy` (`style-src 'self'`) refuses a CDN style. With
  Leaflet's layout rules missing, the tile panes stacked in normal document flow: the map showed a
  small pile of tiles in the middle of a page about 2000 px tall, and the wind barbs — absolutely
  positioned div icons — never appeared. Leaflet's CSS is now imported in `src/main.tsx` and bundled
  into the app's own hashed asset, so nothing in the shell points at another origin. A test reads
  `index.html` and fails if any `href`/`src` is a remote URL, so a CDN dependency cannot come back and
  be blocked again.
- **OpenStreetMap tiles load again (SCRUM-288, also in 0.13.1):** `Referrer-Policy` is
  `strict-origin-when-cross-origin` instead of `same-origin`, which had stripped the `Referer` that
  the OpenStreetMap tile usage policy requires. Their volunteer servers had answered the keyless
  `osm_dark` and `osm_standard` bases with "Access blocked".

---

**Upgrade notes:** no schema, data or configuration change. If a tab still shows an old layout or the
striped "Access blocked" tile, a hard reload clears the cached shell and tiles.
