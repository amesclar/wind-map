# Release Notes - v0.9.2

Release v0.9.2 is a patch release fixing the wind barbs layer. Turning **Show wind barbs across map**
off in Map Settings left the barbs drawn on the map as long as the colour gradient was on — the
toggle appeared to do nothing. The barbs now disappear as soon as their own switch is off.

---

## Fixes

### Wind barbs follow their own toggle (SCRUM-185)
- **Symptom:** with the colour gradient visible, unchecking **Show wind barbs across map** and pressing
  **Done** left every barb on the map, unrotated and still clickable.
- **Root cause:** `MapView` mounted `<WindOverlay>` unconditionally. The shared grid hook stays enabled
  while *either* wind layer is on (`windOverlayVisible || windColorOverlayVisible`, so the gradient and
  the barbs can share one fetch), so with the gradient on the grid points never cleared and the barb
  layer kept drawing from them. With both layers off the points were cleared, which is why the bug only
  showed while the gradient was on.
- **Fix:** the barb layer is mounted only while `windOverlayVisible` is true. The gradient keeps using
  the same shared points, and unmounting already removes the markers and their click listeners — so the
  barbs also stop appearing in map exports when they are hidden.
- **Tests:** a regression test asserts that with the gradient on and the barbs off no barb markers are
  added while the colour overlay still renders, and that turning the barbs back on adds them again.

## Compatibility
- **Behaviour:** the barbs, the gradient and the currents keep their independence; toggling one layer
  leaves the others unchanged. Saved preferences, the forecast-time track and the barb click pop-up
  work as before.
- **API and data:** unchanged. No endpoints, schema, settings keys or stored preferences are touched.
- **Dependencies:** none added or upgraded.
