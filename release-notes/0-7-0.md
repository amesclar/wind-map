# Release Notes - v0.7.0

Release v0.7.0 brings forecast browsing back, rebuilt from the removed drawer into a selector bar
under the map. The app can show the weather for any hour from now up to the selected model's own
horizon, and every pop-up names the hour it describes. The API underneath it learned to serve a
chosen hour, with per-model horizons taken from the model table, run times and hourly caching.

---

## What's New

### Forecast-time API (SCRUM-115)
- **Pick any hour in the window:** `GET /api/weather/grid`, `/api/weather`, `/api/weather/all` and `/api/weather/point` accept an optional `time` — an ISO 8601 instant with an offset, hour-aligned. It returns that hour's wind and temperature in the same response shape as before, with `valid_time` set. Omitting it behaves exactly as it always has: live current values.
- **The window belongs to the model:** each model serves its own horizon, taken from the Time Horizon column added to `frontend/src/assets/weather-models.md` — 7 days for Open-Meteo Best Match, 15 for ECMWF IFS, 16 for NOAA GFS and 7.5 for DWD ICON. A time outside it, before now, misaligned or without an offset is rejected with `422` and a message naming the limit (`time is beyond the best_match forecast horizon of 168 hours`).
- **One source of truth, guarded:** `config.MODEL_METADATA` mirrors the table (cadence, UTC cycle hours and horizon) and a pytest test parses the markdown and fails when the two drift.
- **`GET /api/weather/models`** now reports `update_hours`, `update_cycles_utc`, `horizon_hours`, `last_run_utc` and `next_run_utc`, so the UI never hardcodes a cadence or a window. Run times are derived from the cycle hours (the Forecast API does not expose them) and labelled as the model *run*.
- **Hourly caching:** grid points and both forecast caches are keyed by hour, so scrubbing reuses hours already fetched. `SCHEMA_VERSION` 3 recreates the cache tables on the first start.
- **Plumbing:** `validTime` reaches `useWindGrid`, `useAllWeather` and `MapView`; the model update guide gained the Time Horizon column.

### Forecast time selector (SCRUM-127)
- **A bar under the map, not over it:** the selector sits in normal flow below the map, so the map, the colour legend and the attribution stay fully visible — no overlapping overlays.
- **What it tells you:** the selected model with its update frequency, time horizon and last/next run, read from `/api/weather/models` — for example `NOAA GFS Seamless · every 6 h · 16 days · run 16:00 GMT-8 (next 22:00 GMT-8)`.
- **A track from now to the horizon:** one letter per local day, a marker for now, and a handle that moves in one-hour steps. Drag or click the track, step with the arrows (disabled at the ends), or press Now to return to live values.
- **Keyboard:** left/right step, Home and End jump to the ends, Space plays or pauses. The handle is an ARIA slider whose `aria-valuetext` is the readable time, e.g. `Sun 22 Nov 20:00 GMT-8`.
- **Playback:** play advances 3 hours per tick (one tick per second), waits for each step's data before moving on and stops at the end of the window.
- **Everything moves together:** barbs, saved-location markers and the colour gradient all redraw for the chosen hour, and both pop-ups (saved location and barb) name it.
- The selected hour is memory-only, so a reload opens at "now".

### Drawer removal (SCRUM-126)
- The 48-hour timeline drawer is gone, along with its three-hour forecast slices; a clicked barb now opens its own pop-up with the values and units.
- The colour legend is a fixed 24 px strip under the map, and nothing overlays the attribution.

## Compatibility
- **API:** additive. Without `time`, every endpoint returns exactly what it returned in v0.6.0, with `time: null` and no `valid_time`.
- **Data:** caches are recreated on the first start (they only ever held short-lived weather). Saved locations, preferences and units are untouched.
- **No new dependencies.**
