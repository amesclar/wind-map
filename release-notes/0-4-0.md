# Release Notes - v0.4.0

Release v0.4.0 introduces the user preferences pop-up modal, enhances Docker efficiency and Python dependency pinning, adds comprehensive GitHub Actions CI/CD security and quality pipelines, and establishes unified multi-agent governance and quality rules across the repository.

---

## What's New

### UI & Features
- **Preferences Pop-up Modal (SCRUM-107):**
  - Moved timezone, temperature unit (°F/°C), wind speed unit (knots, km/h, mph, m/s), and wind direction display (barbs, cardinal, degrees) from the top navigation bar into a clean, dedicated Preferences modal opened via a gear icon.
  - Decoupled temperature and wind speed unit selection so toggling °F/°C no longer overrides wind speed preferences.
  - Added persistent local storage for unit preferences and timezone across page reloads.
  - Enhanced layout responsiveness so navigation controls and search remain accessible and readable on mobile and narrow viewports.
- **Forecast Drawer Cleanup (SCRUM-97):**
  - Removed humidity readings from the forecast drawer cards to streamline and declutter the display.

### Performance & Containerization
- **Alpine Runtime Migration (SCRUM-102):**
  - Migrated the production Docker container to `python:3.11-alpine`, substantially reducing container image footprint.
  - Separated development dependencies from the core production runtime requirements.
- **Pinned Dependencies (SCRUM-103):**
  - Implemented reproducible Python dependency locking using `pip-compile` (`requirements.txt` and `requirements-dev.txt`).

### CI / CD & Quality Gates
- **Automated CI Pipelines (SCRUM-108):**
  - Added GitHub Actions CI workflows enforcing automated security scans (Trivy container scanner, CodeQL SAST, pip-audit, npm audit).
  - Enforced code quality standards with `ruff`, backend test coverage thresholds with `pytest --cov`, and frontend lint/typecheck/coverage gates.

### AI Governance & Workflow Rules
- **Multi-Agent Steering Rules Parity (SCRUM-119, SCRUM-128):**
  - Established `.kiro/steering/*.md` as the single source of truth for repository rules and automated synchronization (`scripts/sync-ai-rules.py`) to Antigravity, Devin, and Gemini (`GEMINI.md`, `AGENTS.md`, `.config/antigravity/instructions.md`).
- **Feature Branch & Ticket Workflow (SCRUM-94, SCRUM-111):**
  - Mandated dedicated `feature/SCRUM-xxx` branches for all changes; strictly prohibited direct commits to `develop` or `master`.
  - Enforced immediate branch cleanup (local and remote deletion) post-merge.
  - Formalized planning vs execution boundary: "Create ticket to..." creates the plan and pauses until explicitly instructed to proceed.
- **Jira Automation & Traceability (SCRUM-101, SCRUM-105, SCRUM-118, SCRUM-129):**
  - Required Fibonacci story point estimates on all created tickets.
  - Enforced explicit Jira issue dependency links (`Blocks`, `Relates`).
  - Automated merge commit hash recording on Jira tickets after merging.
  - Automated Jira ticket transition to `Done` following successful PR merges.
- **Release Versioning & Release Notes (SCRUM-130):**
  - Mandated saving structured release notes in `release-notes/x-x-x.md` for all releases.
