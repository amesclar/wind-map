# Release Notes - v0.12.0

Release v0.12.0 makes the feedback form carry evidence and gives the forecast a second opinion.
**Attachments** put files and pasted screenshots on the issue in one request; **NOAA NWS NDFD**
joins as a second forecast provider for saved locations; the model clock and the refresh button now
follow Open-Meteo's real published run times. Around them: the dead ECMWF option is replaced, AIFS
and GEM join the model list, missing values read as "No data" instead of calm wind, tide heights and
their next highs and lows appear in pop-ups, current chevrons stop landing on land, pop-ups stay
inside the map, and the export legend grows a sixth barb example and larger type.

---

## What's New

### Feedback attachments (SCRUM-219, SCRUM-220)

- **Files with the form:** up to **3 files, 4 MiB each, 12 MiB in total**, sent with the feedback in
  one multipart request and attached to the Jira issue. PNG, JPEG, GIF, WebP, PDF and plain-text logs
  (`txt`, `log`, `csv`, `json`) are accepted and identified by their content, not their extension.
- **One request, bounded:** the backend enforces the caps while streaming, refuses an oversize body
  with 413 before reading it, and keeps the whole request under Cloud Run's 32 MiB limit. If the issue
  is filed but Jira refuses an upload, the success screen says the files could not be attached and
  that no retry is needed.
- **Paste a screenshot (SCRUM-220):** paste into the open dialog and the image joins the list as
  `screenshot-YYYYMMDD-HHMMSS.png`. One over 4 MiB is re-encoded as JPEG at falling quality, then
  scaled down if needed, labelled "shrunk from 7.8 MB"; if it still cannot fit, the form says to
  capture a smaller area. Pasted text keeps going into the focused field, and picked or dropped files
  are never re-encoded.

### Second forecast provider: NOAA NWS NDFD (SCRUM-245, SCRUM-106)

- **NDFD as a model:** `nws_ndfd` is offered like the other models for saved locations and ad-hoc
  points, served from `api.weather.gov`. It is the US only: a point outside it answers 404 with a
  fixed message, and a list that includes such a point leaves that location out rather than showing a
  forecast from another provider.
- **How it reads:** `/points` maps a coordinate to its forecast office and grid cell and is cached
  permanently (a coordinate's grid does not move); each hour's `/gridpoints` answer joins the normal
  30-minute forecast cache. Six-hourly NDFD periods repeat across the hourly slices instead of being
  averaged.
- **What it cannot do:** one request per point, so the wind grid, the colour gradient and the currents
  stay on Open-Meteo whichever model is selected.
- **Politeness:** NWS asks for an identifying User-Agent and answers 403 to an empty one, so the app
  sends a real contact, warns at startup when `NWS_USER_AGENT` is unset, and retries a 5xx/429 twice
  before giving up.

### Model clock from real run times (SCRUM-256, SCRUM-113, SCRUM-257)

- **Published run times:** `/api/weather/models` now reports each model's real run availability from
  Open-Meteo, so the footer's model line shows the run the data actually came from instead of a
  computed guess.
- **Refresh gate:** **Refresh data now** stays disabled until the model has published a newer run than
  the one on screen. Hovering the disabled button explains when fresh data will be available, and the
  button enables by itself when that time passes.

### More models, honest gaps (SCRUM-226, SCRUM-227, SCRUM-228, SCRUM-225, SCRUM-232)

- **ECMWF IFS fixed (SCRUM-226):** `ecmwf_ifs04` stopped returning data and rendered every point as
  calm 0 kn at 32 °F; it is replaced by `ecmwf_ifs` (15-day horizon).
- **ECMWF AIFS (SCRUM-227):** the AI forecast model, 15 days, marked as having no gust field.
- **CMC GEM (SCRUM-228):** Canada's global model, 10 days.
- **Missing values are no data (SCRUM-225):** a null from the API no longer becomes 0 kn and 32 °F.
  The map shows **No data** at those points, the wind grid omits them, and a partially covered model
  no longer draws false calm wind.
- **Model guide removed (SCRUM-232):** the toolbar button and its static table are gone; the model
  line under the time selector stays.

### Tides in every pop-up (SCRUM-195, SCRUM-250)

- **Tide rows:** a wind barb's pop-up and a saved location's pop-up show the current tide height with
  the last and next high and low, then the following high or low as a fourth row, in the selected
  units and local time.

### Currents (SCRUM-237, SCRUM-238)

- **Higher contrast:** chevrons use a brighter palette with a dark rim, so they read on the dark
  bases, the paper chart and Seamap alike.
- **No more land chevrons:** a chevron is placed at the requested grid point instead of the model
  cell, and cells that fall on land are dropped, so Camano Island no longer shows current arrows.

### Pop-ups that stay put (SCRUM-248, SCRUM-251, SCRUM-252)

- **Nothing opens by itself:** the map still centres on your location, but no details pop-up opens on
  load.
- **Edges:** a pop-up opens fully inside the visible map panel near the viewport edge, and stays open
  when the map auto-pans under it.

### Exports (SCRUM-240, SCRUM-243, SCRUM-249, SCRUM-258)

- **Six barb examples:** the legend shows calm, 5, 10, 15, 20 and 50 kt, with a measured layout that
  keeps every caption intact at the narrowest export width.
- **Larger chrome:** the export's barb glyphs (32 px), their title and captions (10 px) and the footer
  reference line (10.5 px) are bigger, in taller bands that keep the spacing.
- **Landscape by default:** a PDF export starts in landscape.
- **Footer:** the model and refresh line under the time selector is one size larger.

## Fixes and hardening

- **No coordinates in logs (SCRUM-253, SCRUM-106):** request coordinates and the URLs that embed them
  are never written to the log; upstream failures log the exception type only, so Cloud Logging no
  longer receives a user's position through an httpx traceback.
- **GitGuardian alert (SCRUM-254):** the Basic-auth test password is generated at runtime instead of
  living in the repository.

## Rules

- **Epic for a split (SCRUM-247):** when a ticket is split into two or more tickets and no epic fits
  the resulting work, create an epic and parent every result to it.

---

**Upgrade notes:** no schema or configuration change. `NWS_USER_AGENT` is optional but recommended;
without it the app sends its repository URL and logs a startup warning. The new feedback attachment
limits are server-side (`FEEDBACK_MAX_*` in `backend/app/config.py`) and the app refuses to start with
a total cap at or above Cloud Run's 28 MiB request margin.
