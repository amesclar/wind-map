# Release Notes - v0.14.1

This release is about knowing where you are. The zoom control shows the level it is at, and that
level travels with a version copy and a feedback ticket, so a report says which view produced it.
Map Settings opens as a short list of names with the long explanations behind a circle-i, and the
navbar button names the base map you are on. Under the hood the backend now counts the Open-Meteo
calls it spends, so the free-versus-paid question can be answered from the daily peak rather than an
estimate.

---

## Changes

- **A zoom control that reads its own level (SCRUM-319):** the +/- buttons at the top right are the
  app's own, with the live zoom between them, so the level is visible and it follows wheel, keyboard
  and button zooms alike. Selecting a saved location, or clicking a wind, wave or current glyph, now
  moves the map without resetting the zoom: the flight keeps the level you set, and on the paper
  chart it is raised to the chart's own floor rather than forced to a fixed default.

- **A version badge worth clicking (SCRUM-319, SCRUM-320):** clicking the version badge copies
  `Wind Map v<version>` with the map zoom, your timezone and the browser's user agent — the same
  block the feedback ticket files — and says `<version> copied to clipboard` for a moment, or that
  the copy failed. The map reports its live zoom up to the app, so a ticket made at zoom 12 records
  `Map zoom: 12` beside the version; the backend accepts it from 0 to 30, refuses anything outside
  with 422, and prints `unknown` when a browser sent none.

- **Map Settings, much shorter (SCRUM-322, SCRUM-323):** the base maps now read OSM-Dark, OSM-Light,
  CARTO, NOAA, OpenWater and Satellite instead of their long product names, while the descriptions,
  badges and behaviour are unchanged. Every base map and layer row carries a circle-i button that
  reveals its explanation — attribution, coverage limit, export restriction — in an inline panel,
  one open at a time. The `Not for navigation` notices stay visible with their rows rather than
  hiding behind the glyph.

- **The Map button names your map (SCRUM-326):** the navbar button that opens Map Settings shows the
  selected base map's short name instead of "Map", from the same table the radios use, so the button
  cannot drift from the layer it describes. The icon, the CARTO-key dot and the tooltip are
  unchanged.

## For developers

- **Open-Meteo usage is measured, not estimated (SCRUM-327):** every upstream attempt, retries
  included, records the response's own `X-RateLimit-Cost` with its `-Limit`, `-Remaining`, `-Window`
  and `-Reset` headers, the UTC hour and day, an endpoint label and the outcome, into a new
  `open_meteo_usage` table. The charge the upstream reports is stored instead of the weight formula
  being recomputed, and a quota rejection is logged at cost 0 because it was not charged. Rows are
  buffered and written every 30 seconds or 100 rows and once at shutdown, and a database failure
  logs a warning rather than failing a forecast. `GET /api/weather/quota` reports the 10,000-call
  daily limit, today's calls and peak hour, the last 14 days and the latest headers seen. The table
  sits outside the cache DDL so a schema bump keeps it — these rows cannot be refetched — and rows
  are pruned after 90 days, with one warning per UTC day at 80% of the limit.

- **Rules that load when they matter (SCRUM-321):** `AGENTS.md` keeps only the rules every task
  needs and points at the steering and skill files for the rest, so the always-on context is smaller
  and the situational rules are read when their work starts.

- **The self-host spike is on the record (SCRUM-328):** the SCRUM-236 measurements — README,
  replay/session/usage scripts and the local cold, local warm and production result files — are
  archived under `.kiro/specs/scrum-236/` with their reproduce commands updated, and the spike
  branch is gone.

---

**Upgrade notes:** the schema goes to version 11, which adds the `open_meteo_usage` table. Nothing
else changes: existing caches, saved locations and settings carry over, and no configuration or
secret is needed. `/api/weather/quota` is readable as soon as the new image is running.
