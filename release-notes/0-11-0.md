# Release Notes - v0.11.0

Release v0.11.0 puts real nautical charts on the map. **Paper Chart** draws NOAA's own chart — soundings,
depth contours, lights and aids to navigation — as a base map, and **Seamap** adds Open Waters' vector
nautical detail where the raster chart stops. Around them: optional CHS depth for B.C. waters, an
OpenSeaMap seamark overlay, crisper wind barbs that read on a white chart sheet, and exports that wait
for the map to finish drawing before capturing it.

---

## What's New

### Paper Chart base (SCRUM-203, SCRUM-200)

- **The chart:** a fourth base map in Map Settings renders NOAA Office of Coast Survey's paper chart
  (WMS, layers for chart information, features, soundings, obstructions and aids) as an opaque base.
  It is the NOAA raster product itself, so soundings, contours, light characteristics and buoy symbols
  are the chart's own, at print legibility.
- **Zoom floor:** selecting the chart snaps the map to z12, the shallowest zoom at which the service
  draws a real chart, and the base stops requesting tiles below it. The app opens at z8, so this snap
  happens once, on selection.
- **Coverage:** NOAA chart coverage stops at the Canadian border. The chart is clipped at 49.6 °N and
  the cut is drawn as a dashed chart-ink rule with a notice naming the limit, instead of the chart
  simply stopping mid-water. North of the line the normal base map shows through.
- **Light-sheet contrast:** the chart is a light sheet, so the wind barbs switch to the darker
  temperature ramp, get a dark outline plus light ring when selected, and the colour gradient is
  attenuated over the chart so soundings stay readable. The exported legend follows the same ramp.
- **Declutter:** at the chart's native zoom the 80 px barb grid crowds the soundings, so every second
  point is dropped on a checkerboard and any point within 30 px of a saved location gives way to that
  location's labelled barb. Deeper zooms draw every point.
- **Seamarks on the chart:** NOAA's chart already draws aids to navigation, so the OpenSeaMap overlay is
  hidden while the chart is on (the stored preference is untouched) and a note in Map Settings says so.
- **Failures:** a run of chart tile errors shows a chip naming the cause with a **Retry chart tiles**
  button; the base map keeps showing underneath instead of a blank pane.

### Seamap base (SCRUM-206, SCRUM-201, SCRUM-207)

- **The style:** a fifth base map renders Open Waters' Seamap vector style through MapLibre GL — depth
  shading, navigation aids and labels that stay crisp instead of a raster that blurs.
- **Lazy:** MapLibre and the Leaflet plugin are only downloaded when Seamap is selected (about 1.1 MB
  of JavaScript, split into its own chunk; the rest of the app never pays for it).
- **Layering:** the vector layer draws in the chart pane above the dark substrate, with pointer events
  off, so the barbs, gradient and saved locations stay on top and clickable.
- **Zoom:** Seamap tiles stop at z14 and MapLibre overzooms them, which keeps labels sharp where a
  raster base would blur. The app's own 19-zoom ceiling is unchanged.
- **Credits:** the map and the exported footer carry the Open Waters and OpenStreetMap credits and the
  not-for-navigation notice.

### B.C. depth context (SCRUM-205)

- **CHS NONNA:** an optional overlay of the Canadian Hydrographic Service's NONNA 10 m bathymetry for
  B.C. waters, where the NOAA chart has no coverage: shaded depth and contours at 0.7 opacity so the
  base map, labels and wind layers stay legible. Off by default (it is an extra overseas request per
  tile), persisted like the other layer toggles.
- **Credits:** while it is on, the export footer adds the CHS credit and the not-for-navigation notice.

### Seamark overlay (SCRUM-175)

- **OpenSeaMap:** an optional seamark layer (buoys, lights, beacons) over any base except the paper
  chart, off by default, persisted. Its credit and the not-for-navigation notice join the exported
  footer only while it is on.

## Improvements

### Wind barbs

- **Crisp outline (SCRUM-208, SCRUM-218):** every barb is drawn with one tight dark SVG outline instead
  of a blurred CSS glow, so the glyph stays sharp at 40 px and reads on both the dark bases and the
  white chart sheet.
- **Sizing (SCRUM-209):** grid barbs are sized for the drawn glyph rather than its box, so the grid is
  less crowded at the chart's native zoom; the selected barb is larger and ringed.
- **Gusts (SCRUM-210):** the grid response now carries `wind_gust_knots`, and a clicked barb's pop-up
  shows the gust in your speed unit next to the sustained wind.
- **Gradient on light bases (SCRUM-213, SCRUM-216):** the lighter gradient and the darker temperature
  ramp are shared rules rather than chart-only special cases, and the exported legend matches whichever
  ramp is drawn.

### Exports

- **Readiness (SCRUM-204):** a capture waits for in-flight tiles (including the window before Leaflet
  creates their images) and for a registered vector renderer to go idle, all within the existing five
  second budget, so a pan or a layer change cannot produce a half-drawn image.
- **Grid readiness (SCRUM-242):** a current-view PNG, JPEG or PDF also waits for the wind grid to land,
  because the barbs are refetched after every pan or zoom; without it an export taken right after a pan
  saved the chart with no barbs.
- **Failure reporting (SCRUM-241):** a failed export now says so in the dialog and keeps every option —
  format, page, orientation and file name — so the same export can be retried. An oversized canvas or a
  PDF library that failed to load gets a readable message instead of a broken file.
- **Self-healing tabs (SCRUM-241):** after a rebuild, a tab holding an old lazy chunk reloads itself
  once instead of failing, and the shell is served `Cache-Control: no-cache` while `/assets` stays
  immutable.

## Deployment

- **Cloud Run only from `master` (SCRUM-223):** a merge into `develop` now rebuilds the local container
  and stops there; Google Cloud changes only when a release merges into `master`, or when a branch is
  deployed on purpose from the Actions tab. No automatic deploy trigger exists for `develop` or feature
  branches.

## Compatibility

- **API:** no breaking changes. The wind grid response gains `wind_gust_knots`; every other endpoint,
  response shape and CORS rule is unchanged.
- **Data:** saved locations, settings keys and preferences are untouched; no schema change.
- **Dependencies:** the frontend adds `maplibre-gl` and `@maplibre/maplibre-gl-leaflet`, loaded only on
  the Seamap base. No backend packages were added or upgraded.
- **Credits and notices:** the chart, Seamap and seamark bases add the provider credits and the
  "Not for navigation" notice to the map attribution and the exported footer.
