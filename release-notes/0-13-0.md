# Release Notes - v0.13.0

Release v0.13.0 adds the ocean, and closes out the review of `develop`. **Waves** join wind as a map
layer with their own grid, arrows and pop-ups; **NOAA RRFS** arrives as a high-resolution model for
North America; the map key explains waves without leaving the layer on. Behind the visible work, the
whole of SCRUM-269 landed: the grid cache writes a day in one transaction, unknown `/api` paths answer
JSON instead of the app shell, bad query parameters answer 422, an exhausted upstream quota answers
503 with its reset time, every response carries security headers, repeated Basic Auth failures slow
down, and the two marine services share one cache.

---

## What's New

### Ocean waves (SCRUM-233, SCRUM-234, SCRUM-263)

- **A third kind of data:** `wave_height`, `wave_direction` and `wave_period` come from Open-Meteo's
  marine API for the visible viewport, drawn as coloured arrows on the water and read in pop-ups with
  the height, the direction it comes from and the period in seconds.
- **Grid and point endpoints:** `/api/waves` serves the viewport grid and `/api/waves/point` the
  pop-up series, both cached per UTC hour and per day in SQLite like the wind and current grids.
- **Arrows stay off land:** a point is dropped when its nearest marine cell is on land or the sea
  elevation says so, so the arrows stop at the coastline instead of running over it (SCRUM-263). The
  key now explains wind and waves together in one place.

### RRFS, the high-resolution North American model (SCRUM-231)

- **`noaa_rrfs`** joins the model list, forecast to 18 hours at 3 km over the continental United
  States, drawn from Open-Meteo's RRFS endpoint.
- **Regional coverage is explicit:** outside the model's domain the map falls back to the global model
  and the notice says which window is covered, rather than showing empty cells as calm wind.

### Smaller visible changes

- **Map settings follow the base map (SCRUM-221):** the modal opens on the layer actually selected,
  so a light or satellite basemap no longer looks like the dark one in the picker.
- **Direction hint (SCRUM-239):** the wind-direction setting now says it only affects the barb details
  pop-up, which is what it does.

### Self-hosted forecast fallback, prepared (SCRUM-265)

- **Ready, not running:** `scripts/open-meteo-fallback.sh` can plan, create, check and delete a
  self-hosted Open-Meteo VM with a pinned image, and the README carries the runbook. Nothing was
  created and nothing is billed; the app still uses the public API until someone activates it.

## Fixes and hardening (SCRUM-269)

### SQLite and the caches

- **One transaction per day (SCRUM-274):** a day's grid is written in a single transaction instead of
  one per hour, the database runs in WAL mode and waits 5 s for a lock instead of failing at once, so a
  refresh no longer collides with a reader.
- **Tides fetch only what is missing (SCRUM-286):** the tide window is filled from the nearest cached
  day outward, so panning along a coast no longer refetches hours it already has.
- **One marine cache (SCRUM-276):** currents and waves shared thirteen near-identical helpers; they now
  sit in `services/marine_grid.py` behind a spec, and each layer keeps only what is its own.

### API contracts

- **Unknown `/api` paths answer JSON (SCRUM-277):** a mistyped or removed endpoint returns a 404 body
  with `detail`, not the HTML app shell that made a client parse a page as JSON.
- **Timezone is validated (SCRUM-271):** an unknown `timezone` answers 422 with `Unknown timezone`
  before any upstream call; the rejected names are cached so a broken client cannot turn into load.
- **Quota exhaustion answers 503 (SCRUM-278):** `/api/weather`, `/api/weather/all` and
  `/api/weather/point` return 503 with `reset_at` and `Retry-After` instead of a misleading 502, and the
  bulk endpoint aborts rather than returning a list with locations quietly missing.

### Security

- **Security headers on every response (SCRUM-272):** `nosniff`, a strict referrer policy, no framing
  and a `Content-Security-Policy` that allows exactly the tiles, fonts and API the app uses.
- **Basic Auth throttle (SCRUM-282):** five consecutive failures from one address open a 60-second
  cooldown that answers 429 with `Retry-After`; a correct password clears the count and `/api/health`
  stays open for the platform's checks.
- **The feedback limit sees the real client (SCRUM-270):** `X-Forwarded-For` is honoured only for
  addresses in the new `TRUSTED_PROXY_IPS` setting, so one client can no longer be throttled as the
  whole proxy — and no client can pick its own bucket by sending a header.

### Startup, requests and code

- **No startup waterfall (SCRUM-284):** the app loads its config, saved locations and land mask
  concurrently instead of one after another.
- **Land mask off the event loop (SCRUM-273):** the wave land test loads on a worker thread during
  startup; peak resident memory was measured at 123.4 MB.
- **NWS through the pooled client (SCRUM-285):** NWS calls use the shared HTTP client with their own
  headers and the same transport retry as Open-Meteo, instead of a client per request.
- **Shared grid maths and quota error (SCRUM-281):** the bbox validation and the 503 body live in one
  place; `useBaseLayers` took the map's five base-layer effects out of `MapView` (718 → 506 lines,
  SCRUM-275); the container ref callback is memoised (SCRUM-283); the image installs dependencies with
  `npm ci` (SCRUM-280); the unused `as_float` helper and its trap are gone (SCRUM-279).

## Rules

- **Rebuild environment contract (SCRUM-262):** the rebuild script's environment forwarding and the
  `/api/config` check that proves a rebuild kept the CARTO key and the feedback switch are documented,
  so a container that lost them is caught rather than called verified.

---

**Upgrade notes:** no schema or data migration; the SQLite file gains `-wal` and `-shm` companions when
the app opens it, and Litestream keeps replicating it. Two settings are worth a look on Cloud Run:
`TRUSTED_PROXY_IPS` is empty by default, so the feedback and auth limits key on the proxy address until
it is set to the platform's proxy range; and the new `Content-Security-Policy` is enforcing, so a tile,
font or API host the app starts using must be added to it in `backend/app/main.py` or the browser
refuses it.
